# Continuum-Care-Network 核心交互流程

- 版本：v0.1
- 配套文档：`design-system.md`（反馈样式）、`pages.md`（页面路由）、`components.md`（页面组件）
- 状态标记：🔵 用户操作 / 🟢 系统动作 / 🟠 分支与边界 / 🔴 错误处理

> 所有流程中出现的 Toast / Alert / 弹窗样式与徽标定义见 `design-system.md` §7。所有表单提交需防重复（按钮 loading + 禁用）。

## 流程 1：注册 → 角色选择 → 档案完善

**触发**：新用户访问 `/register`。
**参与者**：匿名用户、系统。

### 1.1 注册账号

1. 🔵 用户填写账号信息：手机号/邮箱、密码、确认密码。
   - 密码规则：长度 ≥ 8，含字母与数字；实时强度提示条（弱/中/强）。
   - 手机号/邮箱格式实时校验。
2. 🔴 校验失败：字段下方内联错误提示（danger 文案），不提交。
3. 🟢 点击「下一步/注册」，系统校验唯一性（手机号/邮箱已存在 → 表单顶部 Alert「该账号已注册」+ 提供「去登录」链接）。
4. 🟢 注册成功 → 签发登录态（JWT access + refresh），跳转**角色选择**。

**边界**：
- 🟠 网络失败/服务器错误 → Toast「注册失败，请稍后重试」，按钮恢复可点。
- 🟠 注册成功但角色选择中断：用户再登录后进入 `/onboarding` 选择角色。

### 1.2 角色选择

1. 🔵 用户从两张角色卡中选择（患者 / 康复师），选中卡高亮（primary 边框）。
2. 🔵 点击「确认并继续」。
3. 🟢 系统按角色跳转：
   - 患者 → `/onboarding/patient`
   - 康复师 → `/onboarding/therapist`
4. 🟠 角色选择可修改：返回上一步重新选择。

### 1.3 患者档案完善（/onboarding/patient）

1. 🔵 填写基本信息（姓名、性别、出生日期）、健康档案（既往病史、过敏史，可选出院小结上传）、紧急联系人。
   - 必填项：姓名、性别、出生日期、联系电话。
2. 🔴 校验失败：对应字段内联错误，聚焦第一个错误字段。
3. 🟢 提交成功 → Toast「档案已保存」→ 跳转 `/patient` 首页。
4. 🟠 若已存在档案（重复进入）：直接展示已保存内容，可编辑后保存。
5. 🟠 未完成建档时，`/patient` 首页顶部显示引导横幅「请完善个人档案」→ 点击跳 `/onboarding/patient`；完成建档后横幅消失。

### 1.4 康复师资质提交（/onboarding/therapist）

1. 🔵 填写执业信息（姓名、执业机构、执业类别、资格证书编号）+ 上传资质证明材料（必传，多文件：图片/PDF，单文件 ≤ 10MB）+ 擅长方向（多选）+ 简介。
2. 🔴 校验失败：材料缺失 → 上传区红色提示「请上传资质证明材料」；编号格式校验。
3. 🟢 提交成功 → 跳转审核中状态页：
   - 顶部 warning 徽标「资质审核中」；
   - 说明文案「管理员审核通过后即可接收患者」；
   - 按钮「进入工作台」（此时工作台为只读态，患者列表为空）。
4. 🟠 审核结果（异步，见流程 4 关联）：
   - 通过：首页状态徽标变 success「已通过」，患者列表可用。
   - 驳回：状态徽标变 danger「已驳回」+ 显示驳回原因 + 「重新提交」按钮（回到编辑态，保留已填内容）。

## 流程 2：患者-康复师匹配对接

**触发**：患者或康复师需要建立/解除绑定关系。
**参与者**：患者、康复师、管理员、系统。
**前置**：双方均完成档案/资质（康复师资质须已审核通过）。

### 2.1 匹配方式（两种）

| 方式 | 发起方 | 流程 |
| --- | --- | --- |
| A. 管理员分配 | 管理员 | 管理员在管理端为未绑定患者指定康复师 → 直接生效 |
| B. 用户申请 | 患者或康复师 | 一方发起申请 → 管理员审核 → 生效 |

### 2.2 方式 B：患者申请（标准流程）

1. 🔵 患者（未绑定）在「我的康复师」页点击「申请匹配」。
   - 空态引导卡提供「申请匹配」按钮。
2. 🟢 弹出申请面板：选择目标康复师（列表：姓名、机构、擅长方向）+ 可选申请理由 → 提交。
3. 🟢 提交成功 → Toast「申请已提交，等待管理员审核」→ 绑定状态卡变为「待审核」（warning 徽标）。
4. 🟠 管理员审核：
   - **通过**：双方收到站内通知；患者「我的康复师」显示康复师卡（active 徽标）；康复师工作台患者列表出现该患者。
   - **驳回**：申请方收到通知 + 驳回原因；状态回到「未绑定」，可重新申请。

### 2.3 方式 A：管理员直接分配

1. 🔵 管理员在对接审核页「分配患者」入口：选择患者 + 选择康复师。
2. 🟢 系统校验双方状态（患者未绑定、康复师资质通过且未达上限）。
3. 🟢 分配成功 → 双方收到通知，绑定即时生效（同上）。

### 2.4 解绑/更换流程

1. 🔵 患者（我的康复师页）或康复师（患者详情页）点击「申请解绑」，确认弹窗说明后果：解绑后双方数据权限即时回收，患者需重新匹配。
2. 🟢 提交解绑申请 → 管理员对接审核列表出现「待审核解绑」。
3. 🟠 管理员审核：
   - **通过**：绑定关系解除；双方收到通知；数据权限即时回收（患者档案对康复师隐藏，消息历史只读归档）；患者端状态卡变「未绑定」+ 重新匹配入口。
   - **驳回**：申请方收到驳回通知，绑定关系保持。

**边界与校验**：
- 🟠 康复师患者数达上限（默认可配置，如 50）：分配/申请被拒，Toast「该康复师已达接诊上限」。
- 🟠 患者已有绑定关系：不允许重复申请，状态卡显示当前康复师。
- 🟠 康复师资质未通过/审核中：不可被申请/分配（列表不展示或展示 disabled）。
- 🟢 绑定关系变更全部写入审计日志。

## 流程 3：健康数据上报

**触发**：患者上报血压/心率/体温/血氧。
**参与者**：患者、系统（触发告警时：康复师、管理员）。
**页面**：`/patient/health`。

### 3.1 上报主流程

1. 🔵 患者进入「健康数据」页 → 上报表单卡。
2. 🔵 填写指标值（各字段带单位；血压含收缩压+舒张压两个输入框）。
3. 🔴 客户端即时校验（服务端同样校验，双保险）：
   - 空值、非数字、超出合理区间（如体温 30–45°C、SpO2 50–100%）→ 字段下方错误提示「请输入有效数值」，禁止提交。
4. 🟢 点击「提交上报」→ 按钮 loading → 调用 API。
5. 🟢 成功：
   - Toast「上报成功」；
   - 表单清空或保留上次值（默认保留，便于连续记录）；
   - 「今日已上报」摘要更新；
   - 历史列表顶部插入新记录（带状态徽标）；
   - 趋势图即时刷新（最新点高亮）。
6. 🔴 失败：Toast「上报失败，请重试」，表单数据保留。

**边界**：
- 🟠 同一天多次上报：允许（每次独立记录），列表展示多次记录。
- 🟠 网络中断：表单数据不丢失；提供「重试」。
- 🟠 上报后自动进入流程 4（异常校验）——若触发告警，成功 Toast 后弹出告警提示。

### 3.2 历史与趋势查看（伴随流程）

1. 🔵 患者在历史列表/趋势 Tab 查看记录。
2. 🟢 趋势图按时间范围（7/30 天）聚合展示，参考区间以半透明带标注，越界点标红。
3. 🟠 数据为空：图表区显示空态「暂无数据，去上报」。

## 流程 4：异常指标告警

**触发**：健康数据上报后，系统按阈值规则判定异常。
**参与者**：系统、患者、绑定康复师、管理员。
**页面**：患者 `/patient`（告警横幅）、`/patient/health`（告警列表）、康复师 `/therapist/dashboard`、`/therapist/patients/[id]`（告警 Tab）、管理端看板。

### 4.1 触发与通知

1. 🟢 数据上报入库后，系统立即按阈值规则校验（收缩压/舒张压/心率/体温/SpO2，阈值由管理员配置，见 `/admin/thresholds`）。
2. 🟢 判定结果：
   - 在参考区间内 → 记录状态「正常」，不触发告警。
   - 超出阈值 → 创建告警记录，级别判定：
     - **紧急（critical）**：严重越界（如收缩压 > 180、SpO2 < 90），红色。
     - **关注（warning）**：一般越界（如心率 121），橙色。
3. 🟢 通知：
   - 站内通知患者（本人）与绑定康复师（若已绑定）；管理员可在看板查看全局告警。
   - 患者端：首页出现告警 Alert（danger/warning 按级别）+ 通知铃铛红点。
   - 康复师端：工作台统计条告警数 + 患者列表告警徽标 + 看板未处理列表置顶。

### 4.2 患者侧查看

1. 🔵 患者点击首页告警卡片/消息通知 → 跳转 `/patient/health` 告警列表（或详情弹窗）。
2. 🟢 展示：指标名、上报值、正常参考区间、触发时间、级别徽标、康复师回复状态（若已处理）。
3. 🟠 患者无操作要求；患者可看到康复师「已联系/已处理」标记，获得安心感。

### 4.3 康复师处理

1. 🔵 康复师在数据监测看板/患者详情告警 Tab 查看未处理告警。
2. 🔵 点击「处理」→ 处理面板：
   - 选项：已联系患者 / 无需干预（填备注）/ 已安排复查；
   - 备注文本（可选）；
   - 确认后状态变「已处理」，记录处理人、时间、方式，写入留痕。
3. 🟢 患者端对应告警状态同步更新（显示「康复师已处理」+ 备注）。
4. 🟠 未处理告警持续在康复师看板置顶；按时间排序，critical 优先。

### 4.4 阈值配置（管理端，伴随流程）

1. 🔵 管理员在 `/admin/thresholds` 修改某指标上下限。
2. 🔴 校验：下限 < 上限、数值在合理范围（如体温 30–45）。
3. 🟢 保存成功 → Toast + 审计日志记录（操作者、前后值）。
4. 🟢 新阈值对**后续上报**即时生效；历史告警不重算（可在日志说明）。

**边界与校验**：
- 🟠 上报值在客户端被判定异常但服务端判定正常（或反之）：以服务端为准；客户端提示以服务端响应为准。
- 🟠 重复上报同一异常值：每次触发独立告警（可考虑同指标短时间合并展示，v1 保留独立记录）。
- 🟠 告警通知失败（如康复师未绑定）：告警仍记录，患者端可见；绑定后康复师可补看历史告警。
- 🟢 所有告警处理动作写入审计/留痕字段，保证可追溯。

## 流程 5（辅助）：站内消息

1. 🔵 患者或康复师在消息页选择会话 → 聊天窗口。
2. 🔵 输入文本 → 发送。
3. 🟢 消息即时上屏（乐观更新），失败则回滚 + Toast「发送失败」。
4. 🟢 对方收到：会话列表未读数 +1、通知铃铛红点；打开会话后已读回执。
5. 🟠 权限：仅绑定关系双方可互发；跨关系发起在 UI 上不提供入口，接口层同样拒绝（403）。
6. 🟠 图片发送：v1.1 预留，输入框按钮 disabled 提示「即将上线」。

## 流程 6（辅助）：管理员审核（资质/对接）

1. 🔵 管理员进入审核页 → 筛选「待审核」。
2. 🔵 查看详情（资质材料预览 / 申请双方摘要）。
3. 🔵 操作：
   - 通过：确认弹窗 → 状态「已通过」→ 通知申请人。
   - 驳回：必填驳回原因 → 确认弹窗 → 状态「已驳回」→ 通知申请人（含原因）。
4. 🟢 所有审核动作写审计日志。
5. 🟠 二次审核：已驳回的申请可重新提交后再次进入待审队列。
