# 延续康护（Continuum Care Network, CCN）产品需求文档（PRD）

- 版本：v0.1（初始规划）
- 状态：草案
- 维护者：项目组
- 更新日期：2026-08-03

---

## 1. 项目背景

### 1.1 业务背景

目标用户为两类患者：

1. **ICU 出院患者**：已完成紧急救治，度过急性危险期，但仍需持续健康监测与康复指导。
2. **康复医院出院患者**：已完成常规治疗，进入居家康复阶段，仍需专业康复师持续跟进。

这些患者离开医院后，与专业康复师之间缺乏稳定的连接通道。本平台旨在搭建一座桥梁，让患者回家后仍能与专业康复师建立持续联系，获得专业的健康监测、康复计划与沟通支持；康复师则可以通过平台高效管理在册患者，及时掌握患者健康状况，实现"院内救治 — 院外康复 — 居家照护"的连续照护闭环。

### 1.2 产品愿景

让每一位出院患者都能获得连续、专业、可追踪的居家康复照护，降低再入院风险，提升康复质量。

### 1.3 产品目标

- 为患者提供便捷的健康数据上报与康复计划跟踪工具。
- 为康复师提供患者档案管理与多患者并行监测的工作台。
- 通过异常指标告警机制，及时发现患者健康风险，支持早期干预。
- 为平台管理员提供审核与治理能力，保障平台数据可信与合规。

## 2. 目标用户与使用场景

### 2.1 目标用户

| 用户角色 | 说明 |
| --- | --- |
| 患者（Patient） | 出院后需要居家康复与持续监测的人群，通过平台上报健康数据、查看康复计划、与康复师沟通。 |
| 康复师（Therapist） | 具备专业资质的康复治疗师/医生，通过平台管理患者、制定康复计划、查看健康数据、进行远程指导。 |
| 管理员（Admin） | 平台运营方，负责审核康复师资质、患者-康复师对接审核、内容治理与系统管理。 |

### 2.2 典型使用场景

1. **出院建档**：患者出院后注册账号，填写基础档案；康复师注册后提交资质，等待管理员审核。
2. **对接匹配**：管理员（或系统）将患者与合适的康复师建立绑定关系，患者可查看自己的康复师。
3. **日常监测**：患者每日/按需上报血压、心率、体温、血氧等健康指标。
4. **异常告警**：系统根据阈值规则识别异常指标，通知患者与康复师。
5. **康复管理**：康复师为患者制定康复计划，患者按计划执行并打卡，康复师跟踪进度。
6. **沟通交流**：患者与康复师通过站内消息进行咨询与指导。
7. **审核治理**：管理员审核康复师入驻资质与对接关系，保障平台安全。

---

## 3. 角色定义

### 3.1 患者（Patient）

- 注册并维护个人档案。
- 上报健康数据（血压/心率/体温/血氧等）。
- 查看康复计划并打卡执行。
- 与绑定的康复师进行消息沟通。
- 接收异常指标告警。

### 3.2 康复师（Therapist）

- 提交资质信息并通过管理员审核后入驻。
- 查看名下患者的档案与健康数据。
- 制定、调整患者的康复计划。
- 与患者进行消息沟通。
- 接收名下患者的异常指标告警。

### 3.3 管理员（Admin）

- 审核康复师入驻资质。
- 审核/管理患者-康复师对接关系。
- 查看平台运行数据与审计日志。
- 账号治理与内容治理。

## 4. 核心功能需求

### 4.1 用户注册与登录（F1）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F1.1 | 注册 | 支持手机号/邮箱注册，选择角色（患者/康复师），设置密码。密码需符合强度要求（长度 ≥ 8，包含字母与数字）。 |
| F1.2 | 登录 | 使用账号密码登录，签发 JWT（access token + refresh token）。 |
| F1.3 | 登出 | 客户端销毁令牌；服务端支持 refresh token 撤销（可选，安全增强）。 |
| F1.4 | 令牌刷新 | access token 过期后使用 refresh token 换取新的 access token。 |
| F1.5 | 找回密码 | 预留：通过手机号/邮箱验证码重置密码（v1.1 迭代）。 |
| F1.6 | 会话安全 | 密码使用 bcrypt/argon2 哈希存储；令牌携带角色与用户标识；每个受保护接口校验令牌与权限。 |

### 4.2 患者档案（F2）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F2.1 | 建档 | 患者填写基础信息：姓名、性别、出生日期、联系电话、紧急联系人、既往病史、出院小结（可选上传）、过敏史等。 |
| F2.2 | 查看 | 患者本人可查看、编辑自己的档案。 |
| F2.3 | 康复师查看 | 绑定的康复师可查看该患者的档案（含健康相关字段）。 |
| F2.4 | 隐私保护 | 非绑定康复师/其他用户不可查看患者档案；敏感字段（如紧急联系人）仅患者本人可见。 |

### 4.3 康复师档案（F3）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F3.1 | 资质提交 | 康复师提交姓名、执业机构、执业类别、资格证书编号、资质证明材料（上传）、擅长方向、简介等。 |
| F3.2 | 资质审核 | 管理员审核资质；审核通过后方可被匹配、接收患者。 |
| F3.3 | 档案展示 | 患者可查看已绑定康复师的专业信息（资质、擅长方向、简介）。 |

### 4.4 患者-康复师对接/匹配（F4）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F4.1 | 绑定关系 | 每位患者与一位康复师建立绑定关系；绑定后康复师可查看患者数据并为其制定计划。 |
| F4.2 | 匹配方式 | 支持两种方式：管理员人工分配；患者申请/康复师申请后由管理员审核确认。 |
| F4.3 | 解绑/更换 | 患者或康复师可发起解绑申请，管理员审核后生效；解绑后双方数据权限即时回收。 |
| F4.4 | 一对多 | 一位康复师可管理多名患者（默认上限可配置）。 |

### 4.5 健康数据上报（F5）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F5.1 | 指标类型 | 血压（收缩压/舒张压）、心率、体温、血氧饱和度（SpO2）等；支持扩展新指标类型。 |
| F5.2 | 上报方式 | 患者手动录入；预留可穿戴设备/API 接入（v1.1 迭代）。 |
| F5.3 | 历史记录 | 按时间线展示患者健康数据，支持图表化趋势查看。 |
| F5.4 | 数据校验 | 服务端校验数值范围（如体温 30–45°C、SpO2 50–100%），拒绝明显异常输入。 |
| F5.5 | 数据权限 | 仅患者本人、绑定康复师、管理员可查看。 |

### 4.6 康复计划制定与跟踪（F6）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F6.1 | 制定计划 | 康复师为患者创建康复计划：目标、周期、阶段任务（训练动作/频次/时长/注意事项）。 |
| F6.2 | 计划查看 | 患者查看自己的康复计划与当前阶段任务。 |
| F6.3 | 执行打卡 | 患者完成任务后打卡，记录完成情况与反馈（如疼痛评分）。 |
| F6.4 | 进度跟踪 | 康复师查看计划执行进度（完成率、打卡记录、趋势）。 |
| F6.5 | 计划调整 | 康复师可基于执行情况调整计划；调整历史留痕。 |

### 4.7 消息沟通（F7）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F7.1 | 站内消息 | 患者与绑定康复师之间一对一消息沟通。 |
| F7.2 | 消息类型 | 文本消息；预留图片（v1.1 迭代）。 |
| F7.3 | 未读提醒 | 消息列表展示未读数，支持已读回执。 |
| F7.4 | 消息权限 | 仅绑定关系双方可互发消息；禁止跨关系通信。 |
| F7.5 | 合规 | 消息内容留存，管理员可在合规场景下审计（脱敏展示）。 |

### 4.8 异常指标告警（F8）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F8.1 | 阈值规则 | 系统内置各指标的阈值区间（如收缩压 > 180 或 < 90、SpO2 < 90% 等），支持管理员配置。 |
| F8.2 | 告警触发 | 健康数据上报后自动校验，触发告警。 |
| F8.3 | 告警通知 | 通过站内通知同时告知患者与绑定康复师；告警标记紧急级别。 |
| F8.4 | 告警处理 | 康复师可标记"已处理/已联系"，处理记录留痕。 |
| F8.5 | 告警查询 | 患者与康复师可查看历史告警列表。 |

### 4.9 管理员审核（F9）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F9.1 | 康复师审核 | 审核康复师资质：通过/驳回，驳回需填写原因。 |
| F9.2 | 对接审核 | 审核患者-康复师绑定/解绑申请。 |
| F9.3 | 阈值配置 | 维护异常指标告警阈值规则。 |
| F9.4 | 用户管理 | 查看用户列表、停用违规账号。 |
| F9.5 | 审计日志 | 查看关键操作审计日志（登录、审核、绑定变更等）。 |

| 功能模块 | 操作 | 患者 | 康复师 | 管理员 |

| 认证 | 登录/刷新令牌 | ✅ | ✅ | ✅ |

| 患者档案 | 查看绑定患者档案 | ❌ | ✅ | 🔶 |
| 康复师档案 | 创建/编辑本人档案 | ❌ | ✅ | ❌ |
| 康复师档案 | 查看绑定康复师档案 | ✅ | ❌ | 🔶 |
| 对接/匹配 | 申请绑定 | ✅ | ✅ | ❌ |
| 对接/匹配 | 审核绑定/解绑 | ❌ | ❌ | ✅ |
| 对接/匹配 | 查看绑定关系 | ✅（本人） | ✅（名下） | ✅ |
| 健康数据 | 上报本人数据 | ✅ | ❌ | ❌ |
| 健康数据 | 查看本人数据 | ✅ | ✅（绑定患者） | 🔶 |
| 康复计划 | 制定/调整计划 | ❌ | ✅（名下患者） | ❌ |
| 康复计划 | 查看计划 | ✅（本人） | ✅（名下患者） | ❌ |
| 康复计划 | 执行打卡 | ✅（本人） | ❌ | ❌ |
| 消息 | 与绑定康复师沟通 | ✅ | ✅（名下患者） | ❌ |
| 告警 | 接收告警 | ✅（本人） | ✅（名下患者） | ✅（全局） |
| 告警 | 处理告警 | ❌ | ✅ | 🔶 |
| 管理 | 康复师资质审核 | ❌ | ❌ | ✅ |
| 管理 | 阈值配置 | ❌ | ❌ | ✅ |
| 管理 | 用户停用 | ❌ | ❌ | ✅ |
| 管理 | 审计日志 | ❌ | ❌ | ✅ |

**权限设计原则**：

- 最小权限：默认拒绝，按角色显式授权。
- 数据级权限：除角色外，所有数据访问必须校验资源归属（患者仅本人、康复师仅名下患者）。
- 每个受保护接口都必须执行：令牌有效性校验 → 角色校验 → 资源归属校验。
- 管理员对患者数据的访问仅限治理场景并记录审计日志。

## 6. 非功能需求

### 6.1 安全

- 密码使用 bcrypt/argon2 哈希存储，禁止明文。
- JWT：access token 短期（如 30 分钟）+ refresh token 长期（如 7 天），refresh token 支持撤销。
- 全接口 RBAC 校验，杜绝越权访问。
- 敏感字段（手机号、紧急联系人、资质材料）加密存储或脱敏展示。
- 接口限流，防止暴力破解与滥用。

### 6.2 性能

- 常规接口 P95 响应时间 < 500ms（目标）。
- 健康数据列表接口支持分页，图表接口支持时间范围聚合。

### 6.3 可用性与数据

- PostgreSQL 定期备份；关键数据（档案、计划、告警）不可丢失。
- 核心流程（上报、告警、消息）幂等或可重试。

### 6.4 合规

- 遵循最小化收集原则；患者健康数据仅用于康复照护目的。
- 提供数据导出与注销账号能力（v1.1 迭代）。

### 6.5 可维护性

- 前后端分离，接口文档自动生成（OpenAPI）。
- Docker 化部署，一键启动本地开发环境。
